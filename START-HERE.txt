ПЕРЕПЛЁТ — ВЕБ-ПРИЛОЖЕНИЕ ДЛЯ УПРАВЛЕНИЯ БИБЛИОТЕКОЙ

Это инструкция запуска, не пояснительная записка курсовой.

1. ТРЕБОВАНИЯ
Node.js 22.13.0 или новее (рекомендуется актуальная LTS-версия).
Проверьте: node --version
Node.js 20 НЕ подходит: используется встроенный node:sqlite.
Внешних npm-зависимостей нет. Команда npm install не нужна.

2. ЗАПУСК В WINDOWS POWERSHELL
Распакуйте архив в отдельную НОВУЮ папку, не поверх C#-проекта.
Откройте терминал в папке, где лежит package.json.

Создайте администратора (замените пароль собственным):

$env:ADMIN_EMAIL = 'admin@library.local'
$env:ADMIN_PASSWORD = 'Replace-With-Your-Password-123'
npm run admin
Remove-Item Env:ADMIN_PASSWORD
npm start

Откройте в браузере: http://127.0.0.1:3000
Войдите с указанными email и паролем.

Повторно создавать администратора при каждом запуске НЕ нужно.
Последующие запуски: npm start
Остановка сервера: Ctrl+C

Если PowerShell блокирует npm.ps1, используйте npm.cmd:
npm.cmd run admin
npm.cmd start
npm.cmd test

3. ДАННЫЕ
SQLite создаётся автоматически: data/library.sqlite.
Это НОВАЯ база; SQL из старого MySQL-проекта не импортируется.
Добавлены три демонстрационные книги и экземпляры без персональных данных.
Для резервного копирования остановите сервер и скопируйте каталог data целиком.
Не публикуйте data в GitHub. Он уже включён в .gitignore.
Не копируйте пароли и строки подключения из старого C#-проекта.

4. РОЛИ
Читатель: каталог, поиск, карточки, бронирования, свои выдачи,
история, одно продление без просрочки, уведомления, профиль.
Регистрация всегда создаёт читателя категории Adult.
Категорию и дату рождения подтверждает/меняет сотрудник.

Библиотекарь: каталог, экземпляры, справочники, читатели,
выдача, возврат, брони, произведения внутри книг, статистика.
Он не может управлять сотрудниками и назначать повышенные роли.

Администратор: все функции библиотекаря, управление ролями,
блокировка пользователей, журнал действий и его CSV-экспорт.
Создайте библиотекаря через «Читатели» — «Добавить» — роль «Библиотекарь».

При регистрации сотрудником читателя без пароля у читателя пока нет входа.
Для доступа задайте ему пароль в карточке учётной записи.
Самостоятельная регистрация с уже занятым email не привязывает существующую карточку.

5. ПРАВИЛА
Schoolboy: максимум 3 книги, 14 дней.
Student и Pensioner: максимум 5 книг, 21 день.
Adult: максимум 7 книг, 30 дней.
Сотрудник может выбрать срок выдачи 1–90 дней.
Проверяется точный возраст по дате рождения для всех ограничений.
Повреждённые и списанные экземпляры выдавать нельзя.
Повторная выдача одного экземпляра запрещена также уникальным индексом БД.
Бронь закрепляет свободный экземпляр на 3 дня включительно.
Максимум 3 активные брони на читателя; повторная бронь той же книги запрещена.
Выдать забронированную книгу можно только владельцу брони.
Просроченные брони закрываются фоновым заданием раз в минуту, пока сервер работает.
Напоминания о возврате появляются за 2 дня и при просрочке.
Уведомления хранятся в БД; доставка в открытый браузер — SSE, проверка каждые 5 секунд.

6. СПРАВОЧНИКИ И КАТАЛОГ
Перед добавлением книги создайте издательство и нужные справочные записи.
В списках с множественным выбором удерживайте Ctrl (Cmd на macOS).
Роли каждого выбранного автора настраиваются в форме книги.
В дополнительных полях автора можно хранить годы жизни, издательства — страну:
{"birth_year":1799,"death_year":1837}
{"country":"Беларусь"}
Системные роли авторов защищены от изменения и удаления.
Удаление связанных записей запрещено; история выдач не уничтожается.
Для экземпляров «Удалить» означает списание, как в исходной программе.

7. ИНТЕГРАЦИЯ
«Каталог» — «Внешний каталог» — запрос к Open Library.
Результат можно перенести в редактируемую карточку книги.
ISBN, страницы и название подставляются; издательство и авторов выберите
из локальных справочников. Данные извне не сохраняются автоматически.
Для внешнего поиска серверу нужен интернет. API-ключ не требуется.
Ручной ввод работает без интернета. Интеграция не проверена из среды генерации.

8. ТЕСТЫ
npm test
Тесты доменной логики и паролей, интеграционные тесты SQLite,
HTTP-тест регистрации, сессии, CSRF и разграничения доступа.
Тестовые базы изолированы от рабочей базы.
Состояние проверок в среде генерации см. verification.json.
В этой среде установлен только Node 20: интеграционные тесты для node:sqlite
пропущены, не выдаются за успешно выполненные. Их нужно запустить на Node 22.13+.
Проверка интерфейса в реальном браузере также ещё требуется.

9. АРХИТЕКТУРА
server/index.js — HTTP, статические файлы, SSE, фоновые задачи.
server/api.js — REST-маршруты, валидация запросов и права доступа.
server/service.js — библиотечные операции и транзакции.
server/domain.js — правила, даты, валидаторы.
server/security.js — серверные сессии, cookie, ограничения частоты.
server/passwords.js — salted scrypt для паролей.
server/db.js, schema.sql — SQLite, таблицы, индексы и начальные данные.
public/ — адаптивный интерфейс на JavaScript, HTML, CSS.
tests/ — автоматические проверки.

10. GIT И GITHUB
В архив включён локальный Git-репозиторий с начальным коммитом.
GitHub/GitLab-репозиторий автоматически НЕ создан и код никуда не опубликован.
Обязательное требование курсовой о наличии удалённого репозитория пока не закрыто.
Создайте пустой репозиторий у себя и выполните, подставив свой URL:

git remote add origin YOUR_REPOSITORY_URL
git push -u origin main

При последующих изменениях:
git add .
git commit -m "Describe your changes"
git push

11. НАСТРОЙКИ И ОГРАНИЧЕНИЯ
По умолчанию сервер доступен только локально (127.0.0.1).
PORT — порт, HOST — адрес, DB_PATH — путь к SQLite.
Например: $env:PORT = '3001'
COOKIE_SECURE=true включайте только при работе через HTTPS.
Встроенный HTTP-сервер в этой версии предназначен для локального учебного запуска.
Публичное размещение требует HTTPS, корректной настройки прокси и отдельной проверки.
Фильтрация каталога выполняется на сервере в памяти: масштабирование под большие
фонды и нагрузочное тестирование в эту поставку не входят.
Автоматических миграций старой MySQL-БД, восстановления пароля по email,
электронных платежей, загрузки файлов и публичного развёртывания нет.
